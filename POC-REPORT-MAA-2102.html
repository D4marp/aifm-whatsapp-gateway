MAA-2102 POC report: WhatsApp group messaging from .NET

Summary

What was built: a .NET service that uses a WhatsApp number through WhatsApp Web. The number is linked once by scanning a QR code on a dashboard page. No official Business API is used.

What works, tested with real WhatsApp: sending to groups of 4, 5, 29 and 36 members, scheduled sending, queueing a message from an API call, from a SQL Server insert and from a Hangfire cron job, and reading new group messages into SQL Server. 47 messages were sent during the test, and Hangfire ran 26 jobs with 0 failed.

What is still open: the risk of the number being banned over time, running on a server, and a bug in receiving (see Findings).

Approach

ItemChoice
ConnectionPlaywright drives Edge on WhatsApp Web; QR scanned once from the dashboard, login kept in a local profile
SendingAll triggers write a row to an outbox table in SQL Server; one dispatcher sends it
PacingSend window 08-18, daily cap, wave limit, minimum gap with random jitter
ReceivingLoop reads the chat list, opens groups with new messages, stores them in an Inbound table
ModeRuns without a visible browser window

Key terms

TermMeaning
PlaywrightLibrary that controls a browser from code; here it drives Edge on WhatsApp Web like a person at the screen
OutboxSQL Server table that holds every message to send, with its status
DispatcherBackground service that sends due outbox rows and applies the pacing rules; the only sender
HangfireBackground job library that stores jobs in SQL Server; here it runs the recurring announcement (cron) and only writes outbox rows

Findings

FindingImpact
Unofficial automation breaks WhatsApp termsThe number can be banned; use a number that can be lost
Depends on the WhatsApp Web page layoutThe receive reader needed four fixes in one day after the page differed from assumptions; expect maintenance
One number needs one workerIn the ERP this should be a separate worker process
Opening a group to read it marks it as read on the phoneSide effect of receiving
Receiving reads every synced group, not only the test group4 messages from an unrelated group were stored before receiving was switched off; it needs a per-group allow list
The sync also lists some one-to-one chats as groups (0 members)A test message could be queued to a person by mistake; the list needs a filter
Login was lost once after the process was stopped by forceA new QR scan was needed after the restart; cause not confirmed; the worker must stop cleanly
Group list changes only when a sync is runAfter switching the WhatsApp account, run the sync; the new account's 18 groups then appeared
One send timed out (message box not found in 8 seconds)The retry succeeded; the dispatcher's retry handled it
Pacing held messages as designedMessages stay Pending outside the send window or when the wave is full
