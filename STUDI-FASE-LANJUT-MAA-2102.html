MAA-2102 fase lanjut: studi implementasi dan keamanan

Permintaan

Sistem .NET mandiri dengan database SQL Server sendiri yang mengelola pesan masuk dan keluar (teks, audio, video) untuk beberapa nomor WhatsApp, dengan metode API supaya sistem web lain bisa mengirim pesan keluar dan membaca pesan masuk.

Yang sudah dicakup POC

BagianStatus
Database SQL Server sendiri dengan tabel outbox dan inboundSelesai, hanya teks
API untuk mengantre pesan dan membaca pesan masukSelesai di lab, belum ada autentikasi
Pacing: jam kirim, batas harian, batas gelombang, jeda, jitter acakSelesai, untuk satu nomor
Konektor WhatsApp yang bisa diganti (interface dengan versi fake dan real)Selesai
Beberapa nomor sekaligusBelum: satu nomor = satu profil browser = satu worker
Audio dan videoBelum
Autentikasi API, akses per sistem, status pengirimanBelum
Jalan di serverBelum diuji

Desain target

ERP menjadi satu klien dari API. Tiap nomor punya worker, login, dan pacing sendiri. Pesan dan hasilnya lewat database, jadi worker yang restart tidak menghilangkan pesan yang sudah diantre.

Rekomendasi: pertahankan konektor sekarang untuk teks (sudah terbukti) dan pertahankan interface-nya, sehingga konektor kedua bisa ditambahkan. Di Phase 0, uji satu konektor tingkat protokol untuk media dan beberapa nomor, lalu pilih berdasarkan hasil uji, bukan dokumentasi. Kedua jenis tidak resmi.

Catatan implementasi (usulan, belum dibangun)

KebutuhanCara
Beberapa nomorTabel sesi (nomor, status, lokasi login, pengaturan). Satu worker per sesi dengan folder login atau auth state sendiri, pacing dan batas harian sendiri. Login QR per nomor dari dashboard atau API. Nomor yang sama tidak pernah dipakai di dua tempat
Kirim mediaBaris outbox menunjuk ke catatan media. Worker mengunggah file lewat konektor. Ada batas ukuran dan tipe
Terima mediaWorker mengunduh file dan menyimpannya di luar database (disk atau blob). Database menyimpan tipe, ukuran, hash, dan path. Unduhan gagal dicoba ulang dan ditandai
Kirim pesan keluarPOST dengan nomor, tujuan grup atau kontak, teks atau id media, dan kunci idempotensi opsional. Mengembalikan id. GET status: Pending, Sent, Failed
Baca pesan masukGET pesan masuk setelah kursor, disaring per nomor. Klien mengonfirmasi yang sudah diproses, jadi tidak ada yang terbaca dua kali atau hilang. Webhook sebagai opsi nanti
Tata letak prosesWorker jalan sebagai layanan sendiri, bukan di dalam ERP. API tetap hidup saat worker restart

Keamanan: akun (risiko blokir)

Isi sumber: Ketentuan Layanan WhatsApp melarang pesan massal, pesan otomatis, dan pembuatan akun otomatis. Pedoman Pesan (diperbarui 23 Sep 2026) mencantumkan klien tidak resmi, pesan massal, dan otomasi di bawah perilaku adversarial, dengan batasan "to harm WhatsApp or our users", dan menyebut akun bisa ditangguhkan sementara atau permanen. Kedua jenis konektor tidak resmi, jadi tidak ada yang menghilangkan risiko. Artikel vendor menyebut blokir sering mendadak tanpa peringatan; sumbernya perusahaan yang menjual API resmi, jadi hanya sebagai petunjuk. Tidak ditemukan aturan publik tentang laju kirim yang aman. Pengaturan POC (10 sampai 15 per hari, gelombang) berasal dari saran tim dan belum diverifikasi.

LangkahAlasan
Pakai nomor khusus, bukan nomor pribadiBlokir hanya mengorbankan nomor itu (pelajaran POC: nomor yang tertaut adalah nomor pribadi)
Kirim hanya ke grup dan orang yang memang menunggu pesanPedoman menyebut kontak berulang yang tidak diinginkan sebagai spam
Pacing per nomor: jam, batas harian, gelombang, jeda, jitterMenghindari lonjakan seperti mesin (sudah diterapkan)
Satu worker per nomor, tidak ada login kedua untuk nomor yang samaMenghindari sesi yang bentrok
Jangan membuka dan menutup koneksi berulang cepatSatu artikel vendor mencantumkannya sebagai pola mencurigakan (satu sumber)
Tombol darurat per nomor; berhenti otomatis saat logout atau gagal berulangMenghentikan sebelum kerusakan membesar
Pantau pengiriman, kegagalan, dan logout per nomorMasalah ketahuan lebih awal

Keamanan: sistem

AreaLangkah
Akses APIAPI key per sistem pemanggil, disimpan ter-hash, dibatasi ke nomor yang diizinkan. HTTPS. Pembatasan laju per key
Bahan loginProfil browser atau auth state adalah kunci akun: disk terenkripsi, akses terbatas, tidak pernah di git, zip, atau cadangan yang dibagikan
RahasiaConnection string dan key di luar repositori (vault atau environment)
Data pribadiPesan grup bersifat pribadi. Daftar grup yang diizinkan dibaca per nomor (pelajaran POC: penerimaan menyimpan pesan dari grup yang tidak terkait), masa simpan, log akses
File mediaBatas ukuran dan tipe, pindai malware, tidak pernah dieksekusi, disimpan di luar web root
AuditCatat siapa mengirim apa, ke nomor mana, kapan. Isi pesan tidak ditulis ke log aplikasi
KetahananOutbox ada di database; worker crash tidak menghilangkan apa pun; coba ulang sampai 3 kali (sudah diterapkan)
